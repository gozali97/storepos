# Audit frontend StorePOS

Tanggal: 13 Oktober 2026. Mode: audit terlebih dahulu, perbaikan mengikuti nomor yang dipilih pengguna.

## Arahan pengguna

Redesign mengikuti [Soft UI Dashboard Tailwind](https://github.com/creativetimofficial/soft-ui-dashboard-tailwind), menggunakan tema biru, dengan prioritas layout admin dan halaman login. Arahan ini menggantikan warna Kertas/Tinta/Kunyit untuk aplikasi. Landing page memiliki ruang lingkup terpisah.

Referensi dashboard dan sign-in diperiksa melalui repository resmi. Preview ThemeWagon tidak dapat dibuka melalui alat browsing.

## Temuan yang dapat dipilih

1. **HIGH, R-27 dan C-2: validasi dan pesan kegagalan login belum lengkap.** `app/src/pages/LoginPage.jsx:36` memakai `noValidate`, tetapi handler tidak memvalidasi field sebelum request. Semua error selain rate limit disebut kesalahan kredensial, termasuk gangguan jaringan/server. Perbaikan: validasi field, pesan error sesuai penyebab, hubungan error dengan input, fokus ke input bermasalah, dan status pengiriman yang diumumkan. Login tetap memakai API sesi yang ada.

2. **HIGH, R-27 dan C-4: kegagalan pemeriksaan sesi tidak terlihat.** `app/src/auth/SessionContext.jsx:42` mengubah kegagalan jaringan menjadi status tamu dan menyimpan error, tetapi `App` maupun halaman login tidak menampilkan error tersebut. Perbaikan: keadaan gagal memuat sesi dengan tombol coba lagi; hindari memberi kesan pengguna kehilangan sesi ketika server tidak terjangkau. Tambahkan indikator koneksi dengan teks.

3. **HIGH, R-25: batas input kurang kontras.** `app/src/styles/tokens.css` memakai `#dad4c8` untuk border di atas `#fffdf7`. Pemeriksaan menghasilkan 1,45:1, di bawah batas 3:1 untuk komponen interaktif. Perbaikan: token biru dengan teks, batas input, dan fokus yang dihitung kontrasnya; status tetap memiliki pesan tertulis.

4. **HIGH, R-03 dan R-32: header admin belum memiliki perilaku responsif yang jelas.** `HomePage` menempatkan brand, pemilih bisnis, dan logout dalam satu baris; stylesheet tidak menyediakan breakpoint atau navigasi mobile. Perbaikan: sidebar desktop, header yang dapat membungkus, menu mobile berlabel yang bisa ditutup dengan Escape, fokus yang benar, dan skip link. Periksa lebar ponsel, tablet, desktop, serta pembesaran teks.

5. **LOW, R-20 dan R-31: tampilan admin dan login belum mengikuti arahan Soft UI biru.** `HomePage` hanya berisi header dan panel status pembangunan; login berupa satu panel kecil; tokens masih memakai warna kunyit. Perbaikan: layout admin bersama dengan sidebar, breadcrumb, area akun/bisnis dan panel konten; login dengan komposisi dua kolom di desktop dan satu kolom di mobile. Gunakan latar abu terang, permukaan putih, sudut lembut, dan aksen biru untuk aksi utama. Statistik tidak dibuat tanpa sumber data. Bayangan memisahkan permukaan utama dari latar; ikon harus menjelaskan menu, bukan menjadi dekorasi.

6. **LOW, C-2 dan C-3: status task frontend belum sesuai kode yang tersedia.** `TASKS.md` §1.8 masih menandai klien API dan kamus istilah sebagai belum selesai, padahal implementasi serta tesnya sudah ada. Shell juga belum menyediakan pemilih cabang/terminal, code splitting, dan pola keadaan konsisten. Perbaikan: verifikasi implementasi terhadap kontrak API, selesaikan fondasi frontend dan ADR yang diperlukan, lalu perbarui checklist dengan bukti. Halaman operasional berikutnya menggunakan layout admin yang sama; task yang membutuhkan endpoint atau keputusan belum tersedia tetap dicatat sebagai dependensi.

## Pemeriksaan baseline

- PASS: `npm test`, 3 berkas tes lulus: klien API, mesin harga, dan kamus istilah.
- PASS: `npm run build`, Vite membangun 46 modul.
- PASS: temuan memakai kode dan hasil perhitungan; tidak menambahkan klaim produk atau data dashboard.
- Audit ini memakai inspeksi kode. Klik UI, screenshot, perilaku mobile dan login dengan backend nyata belum diuji.

## Batas persetujuan

Belum ada perubahan desain atau kode aplikasi. Sesuai mode audit, hanya nomor temuan yang dipilih pengguna akan diperbaiki. Persetujuan temuan 6 mencakup peninjauan dan pengerjaan task frontend yang diminta pengguna, dengan prioritas layout admin/login; setiap dependensi yang nyata harus dicatat, dan checklist hanya dicentang setelah kebutuhan terkait diverifikasi.
